# Selected Internet-exposure hardening: implementation status

Updated 2026-09-24. This maps the implemented F1, F2, F4, F5, and F7 work to the [baseline security review](internet-exposure-review-2026-09-23.md), [remediation proposals](internet-exposure-remediation-proposals-2026-09-23.md), and [selected design](../superpowers/specs/2026-09-23-selected-internet-exposure-hardening-design.md). It is **not an Internet-release approval**. F3 HTTPS/trust-anchor and F6 WebRTC transport remain unresolved; no remote deployment profile was selected.

| Finding | Program-enforced change | What remains |
| --- | --- | --- |
| F1: key oracle and short-code guessing | Removed anonymous key inspection/legacy connect routes. A single metered `/api/key-start` checks budgets before lookup; eight-character purpose-neutral codes exclude `0`, `1`, `I`, `L`, and `O`. One-time and registration codes are explicitly host-issued, short-lived, single-use, and globally/per-source attempt-capped. The standing password is restricted to loopback or detected eligible physical Private LAN subnets, with a validated CLI/config override; a handler configured with public scope rejects it. The native Connect device dialog chooses letters-and-digits or letters-only. | Eight symbols are not high-entropy long-term credentials. A short code can be guessed within its bounded budget, stolen, or used before expiry. A same-host proxy into the **local** listener can launder its socket address; remote-mode listener/proxy separation and deployment checks are still needed. Budget exhaustion can deny legitimate attempts. |
| F2: stale or captured control permission | Current approved-client permission and generation are checked at selection, grant, native acknowledgment, and lease renewal. Owner downgrade/removal invalidates authorization synchronously and waits for native denial or peer/stream teardown before success. Failure paths shut down sharing when safe durable state cannot be assured. A separate owner action disconnects existing ordinary sessions. | Input processed before revocation cannot be undone. Mocked media timeout/teardown tests pass, but the actual native worker's revoke-timeout path needs a supported-host exercise before remote release. |
| F4: loopback-proxied diagnostics | `/api/diagnostics` requires both local socket/Host checks and a 256-bit, 15-minute owner-issued bearer capability (at most four live). CLI `diagnostics open` and the Windows host Diagnostics action issue it explicitly. The browser consumes a URL fragment, removes it before fetching, then sends the token only in an Authorization header; no token appears in routine ready/status/startup output. Missing/expired authorization returns `403` without live data. | A stolen unexpired bearer can be replayed through a proxy. A real browser click/expiry UI exercise is still useful; server, bootstrap, and host navigation tests cover the mechanism. |
| F5: approved-client copy and revocation | One approved credential may have only one live session; a second sign-in is refused without displacing the first. Removal and downgrade invalidate admission and active authorization before asynchronous persistence. Authentication rechecks the same generation after password derivation, and removal closes matching sessions/streams. | The IndexedDB secret plus password can still be copied and used when no session is active. The app must call this an approved **browser credential**, not proof of a physical device. Device-held proof or an alternative remote identity profile remains a later decision. |
| F7: unbounded admission work/state | Admission uses rolling server-wide/per-source/per-identity limits, a four-job `scrypt` ceiling, finite maps, and short registration/claim/pending lifetimes. The 64-pending cap, malformed-body charging, and bounded `429`/`503` behavior are tested. TTL, attempt caps, alphabet, and eligible local networks are validated in CLI/config, not exposed as native-host controls. | In-process caps do not absorb volumetric TCP/TLS/WebRTC floods. A future public deployment needs an upstream edge and real-network load validation. |

Verification on this checkout: `npm test` passed 773 tests; `npm run format:check`, `dotnet build apps/windows-host/VidVnc.Host.csproj`, the Windows navigation exercise, and `node apps/server/tests/runtime-start-check.mjs` passed. Tests include a loopback-socket/`Host: localhost` proxy reproduction: no bearer yields `403`, a live bearer yields data, and expiry denies it. The startup exercise verifies token-free ready/status output and explicit owner issuance. The Windows exercise verifies owner-pipe correlation and fragment URL construction, but does not launch a real browser or exercise hardware media.

Remote access remains **not ready** until F3/F6 are designed and verified against the selected network topology, F5's deliberately transferable credential is accepted or replaced for that topology, and the remaining native/hardware, browser, TLS, and deployment checks are completed. Do not forward the current listeners to the Internet merely because these five findings were narrowed or addressed.
